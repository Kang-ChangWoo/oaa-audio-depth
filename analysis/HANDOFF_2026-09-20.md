## 1. The open question the next session must answer first

**Is `STFT_HOP=44` defensible, or does it look tuned to us?**

It is not a conventional hop and it was reached by trying values. A hop has to be justifiable
without reference to our own accuracy. Measured properties of this task (real tensors, win 400,
n_fft 512, 58.3 ms crop):

| hop | ms | real STFT frames | overlap | frames / 32 time tokens | note |
|---:|---:|---:|---:|---:|---|
| 200 | 4.17 | 14 | 50% | 0.44x | hop = win/2, the minimum COLA condition |
| 160 | 3.33 | 18 | 60% | 0.56x | **released recipe** |
| 128 | 2.67 | 22 | 68% | 0.69x | **n_fft/4 — the standard choice in the literature** |
| 88 | 1.83 | **32** | 78% | **1.00x** | **exactly one real frame per time token** |
| 64 | 1.33 | 44 | 84% | 1.38x | n_fft/8, a power-of-two divisor |
| 44 | 0.92 | 64 | 89% | 2.00x | current experiment value |
| 22 | 0.46 | 128 | 94% | 4.00x | |

**The defensible criterion available**: "the coarsest hop that fills the model's time-token grid"
is a property of the architecture, not of our score, and it selects **hop 88** (32 frames = 32
tokens). hop 128 is the more conventional number but leaves the grid underfilled (22 < 32).

Runs in flight to settle this, all on MP3D 4ch (anchors already measured: hop 160 = 0.7744,
hop 44 = 0.7562):
- `0820_s9_h128_mp3d`, `0820_s9_h64_mp3d`  (queued by `0820_queue_hopsweep.sh`)
- `0820_s9_h88_mp3d`, `0820_s9_h22_mp3d`   (queued by `0820_dispatch.sh`)

**Decision rule to apply when they land**: pick the most conventional / most structurally motivated
hop whose MAE is within the campaign tie threshold (0.01) of the best hop. Then retrain OAA-CNN and
EchoDiffusion at THAT hop and report the three-way comparison. Do not pick the hop by our own best
score.

**Prior-work hop values still need to be collected** — the user asked for this explicitly and it is
NOT yet done. The repo's own baselines all inherit `data_0422`'s hop 160, so the numbers must come
from the original papers/implementations (EchoScan, BatVision, Beyond-Image-to-Depth,
EchoDiffusion) rather than from this tree. Conventional references: hop = n_fft/4 is the usual
audio default; AudioSet-style log-mel uses 10 ms hop (160 samples at 16 kHz = 480 at 48 kHz).

## 3. Explanations for the hop gain — three ruled out, one weak

| hypothesis | test | verdict |
|---|---|---|
| more information | hop 160 already satisfies hop <= win/2, so 44 is ~4.5x oversampling | ruled out (analytic) |
| token waste / replication | 32f x 16t regrid: Replica +0.0005, MP3D -0.0080 | ruled out (both ties) |
| time resolution | win 400 -> 100 (143 cm -> 36 cm): all seven metrics worse, MAE +0.0873 | ruled out |
| branch attribution | coarsening fine CNN -0.0037, coarsening AFM +0.0038 | direction only; all four arms within 0.0101, i.e. all ties, single seed |
| **longer acoustic context** | `0820_ctx_C_210ms_h160_mp3d` **still training** | **the remaining candidate** |

Context experiment: source wavs are much longer than the released crop (Replica 1641 ms, MP3D
>= 1147 ms), so no re-rendering was needed. **210 ms at hop 160 gives exactly 64 frames**, matching
58.3 ms at hop 44 (verified on real tensors). Conditions A (0.7744) and B (0.7562) already exist.
- C ~ B  -> frame count / context is what matters
- B > C  -> sampling the short echo densely is what matters
- C < B  -> late reflections themselves carry value

## 4. Microphone scaling (experiment 3)

Dataset is at **`/root/storage/supple_mic_gain`** (the requested `/file2/...` path is not mounted
in this container). Read from `mic_order.json`, not assumed:

- **30-degree yaw grid, not 45**: 12 binaural headings, so **N_max = 24 channels**, not 8
- bisection addition order `0, 180, 90, 270, 30, 210, 120, 300, 60, 240, 150, 330`
- subsets are **nested by construction** (verified: each mode's channel list is a prefix of the next)
- k = 4 reproduces exactly the released r8 input {0, 90, 180, 270}
- 18 scenes x 100 positions, off3 split: train 14400 / val 3600 / test 3600
- the set's README warns the renderer has **no RNG seed**, so yaw 0 is NOT bit-identical to
  replica_0422 (waveform correlation 0.82-0.98). **The scaling curve must be closed inside this
  set** — do not borrow an m8 baseline from the campaign.

`data_micgain.py` exposes modes `m2 .. m24`. `oaa.py` and the trainer accept any even nviews up to
24, and the parameter count is identical at every channel count (100,713,770, verified 2 to 24), so
only the microphone count varies. `0820_queue_micgain.sh` trains all 12; `analysis/micgain_report.py`
generates the report and marks unmeasured cells pending.

EchoDiffusion's 12 scaling runs (priority 4) are NOT queued yet — deliberately, to avoid 24
simultaneous jobs competing for GPUs. Queue them once the Ours curve has shape.

## 5. Infrastructure notes (things that bit me)

- **Dispatchers**: `0820_dispatch.sh`, `0820_queue_micgain.sh`, `0820_queue_fairhop.sh`,
  `0820_queue_hopsweep.sh`. All now re-derive the pending set from the filesystem each sweep
  (a run is settled only when its log contains `[done]`) and retry crashes up to MAX_TRY with the
  dead log archived as `.failN`. The earlier forward-only cursor silently dropped jobs.
- **GPU claim**: per-GPU `flock` plus a check of actual FREE memory (>= 26 GB). Testing
  "used < 2000 MB" killed five runs with OOM on cards already holding a job.
- **git push**: the default credential helper is a dead VS Code remote helper. Use
  `git -c credential.helper=store push origin main`.
- **val does not predict test** in this campaign. It has reversed at least three times (B2 vs
  hop 44, the window experiment, the path separation). **Report no ranking from val.**
- EchoDiffusion trains in its own env: `/root/local1/changwoo/echodiff_env/bin/python`, and needs
  no code change for a new hop — it reads the same data module, so `STFT_HOP` reaches it.
- Env overrides added this session: `STFT_HOP`, `STFT_WIN`, `STFT_NFFT`, `STFT_WINDOW`. All are
  recorded in checkpoint args and `core/ckpt.py` refuses a mismatched data module at eval. Any
  non-default value disables the prebuilt spec cache.
